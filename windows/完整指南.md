# G9N9N 遥控器变 Windows 语音与快捷键遥控器

版本：2026-11-08。把**这一个 Markdown 文件**发给朋友即可，补丁和已测试依赖已内嵌，不需要原作者的电脑、配置、录音或另一个附件。

朋友可以对自己的 Agent 说：

> 请先完整阅读这个文件，按里面已经验证的路线，帮我把 G9N9N 遥控器配置成 Windows 的语音输入和按键遥控器。请实际操作并保存过程记录，需要我按遥控器、确认管理员提示或重启时再叫我。必须验证普通视频仍能出声，以及遥控器说话能真正变成中文，不能只看“已连接”。遇到无法解决的差异，给我证据和具体卡点。

## 1. 已验证范围与最短路线

现场验证环境：Windows 10 22H2（19045）、Intel 蓝牙、Google Chromecast Voice Remote G9N9N，VID 18D1 / PID 9450 / REV 0110。实际按键为 8 字节报告，且已验证真实中文上屏、普通键映射、侧面音量键。Windows 11 可走同一路线，但不能把这一台 Windows 10 的验收当成所有机器都必过。

成功链路：

```text
G9N9N 蓝牙 → 无线麦Mod 的设备专属 HID 接收 → Windows 快捷键
G9N9N 麦克风 → ATVV 蓝牙音频 → 无线麦Mod → CABLE Input
→ CABLE Output → 微信输入法的语音转写 → 当前文字输入框
```

G9N9N 本身不会自动成为 Windows 标准麦克风。蓝牙“已连接”也不代表按键或语音已可用。**不用再同时试装多个桥接程序。**

必需：G9N9N、两节正常的 AAA 电池、支持 BLE 的 Windows 蓝牙、Python 3.14 x64、Git、本文固定的无线麦Mod、VB-CABLE、微信输入法。没有额外的付费语音 API、硬件桥接板或 Codex/Claude CLI 依赖。需要网络下载依赖、微软调试符号以及使用输入法的在线转写。

## 2. 给接手 Agent 的执行边界

- 自己选择本机实际存在的工作目录，所有本次脚本、下载、日志、备份放那里。不要照搬别人的 D 盘路径。
- 用 PowerShell。先盘点 Windows、Python、蓝牙、声卡、已装桥接程序和虚拟声卡，并保存当前默认播放/录音设备、静音状态。修改配置先备份。
- 保留原有键鼠和正常声音输出。只按本只遥控器的设备身份过滤，不能把全部物理键盘一起重绑。
- 不关闭安全防护，不自动重启电脑，不禁用整个蓝牙/HID 栈，不反复恢复遥控器。UAC、物理配对和按键测试由机主配合。
- 不复制本指南作者的 MAC、Container ID、活动设备 key 或 config.json。设备身份必须在朋友自己的机器上生成。
- 软件能导入、日志订阅成功、显示“已连接”、电平跳动，都不能替代实际验收。
- 不要在普通用户的既有脏工作区执行 reset、强制切分支或覆盖。以下源码命令用于本次新建目录。

## 4. 一次性安装与配对

1. 检查已有 `CABLE Input` 与 `CABLE Output`。已有正常设备时直接跳过安装，不要反复安装造成重复设备。
2. 缺少时只从 [VB-Audio 官网](https://vb-audio.com/Cable/) 下载 VB-CABLE，解压后以管理员运行适合系统架构的安装器。官网要求安装后重启；需要机主保存工作并亲自确认重启。不要把驱动安装器捆进本指南或使用不明镜像。
3. 安装或检测 [微信输入法](https://z.weixin.qq.com/)。使用其语音功能，不需要 API Key。
4. 新遥控器按住“返回 + Home”约 3 秒进入配对，在 Windows 添加蓝牙设备，选择 `Chromecast Remote`。如果已配对，先检查是否能通信，不要一上来就解除配对。
5. 如有另一台电视曾经配过这只遥控器，先确认它不会抢连。本文现场设备此前没连过电视，不能把“被电视抢连”当作所有失败的原因。

## 6. 配置语音和普通键

**声音路由必须分开：**

| 位置 | 应选内容 |
|---|---|
| Windows 正常播放输出 | 用户平时的电脑扬声器、耳机或 HDMI 电视，先实播确认 |
| 无线麦Mod 的语音输出端点 | `CABLE Input (VB-Audio Virtual Cable)`，优先 Windows WASAPI |
| 微信输入法“语音输入”的麦克风 | `CABLE Output (VB-Audio Virtual Cable)` |
| 自动压音 | 默认关闭，避免音频恢复/输出切换的额外变量 |
| 关闭音频发送 | 必须关闭，否则会丢弃遥控器音频 |

不要为了遥控器把 Windows **播放**输出改成 CABLE Input，也不要把 CABLE Output 强制设成全局默认麦克风。驱动安装可能自动改变默认项，安装后应检查并恢复；本方案只需在微信输入法内单独选麦克风。

微信输入法设为“按住说话”。本次快捷键为 `Ctrl+Win`，朋友电脑须读实际页面核对，并使桥接程序的快捷键完全一致。快捷键不同就修改配置，不假设所有版本都一样。

推荐通过软件“语音”和“按键”页直接配置。若 Agent 使用文件配置，先正常完全退出程序，备份这两个配置文件，再按**本机实际活动 key**修改，不可在运行中覆盖：

```powershell
$env:PYTHONPATH = Join-Path $repo 'src'
$env:REMOTE_MIC_DEV_SESSION = '1'
& $python -m ovb --request-exit --remote-mic-dev-session
```

可将以下保存为 `$repo\Configure-Remote.py`。只在完成“使用此设备”后运行；这是推荐默认方案，朋友已有自定义时先核对，不能覆盖其他设备的配置：

```python
import json
import re
import shutil
from datetime import datetime
from pathlib import Path

root = Path(__file__).resolve().parent
backup = root / 'config' / ('before-agent-' + datetime.now().strftime('%Y%m%d-%H%M%S'))
backup.mkdir()
config_path = root / 'config' / 'config.json'
keys_path = root / 'config' / 'key_bindings.json'
for path in (config_path, keys_path):
    shutil.copy2(path, backup / path.name)
config = json.loads(config_path.read_text(encoding='utf-8-sig'))
keys = json.loads(keys_path.read_text(encoding='utf-8-sig'))
active = config.get('remote_selection', {}).get('active', '')
if not re.fullmatch('[0-9a-f]{64}', active):
    raise SystemExit('先在界面选择自己的遥控器，不猜设备身份。')
record = config.setdefault('remote_settings', {}).setdefault('records', {}).setdefault(active, {})
voice_hotkey = 'lctrl+lwin'  # 必须与本机微信输入法页面一致。
record.update(output_endpoint_host_api='Windows WASAPI',
              output_endpoint_name='CABLE Input (VB-Audio Virtual Cable)',
              voice_hotkey=voice_hotkey,
              remote_recording_mode='hold', voice_trigger_mode='hold')
record.setdefault('voice_program', {})['provider'] = 'wetype'
record.setdefault('voice_hotkeys', {})['hold'] = voice_hotkey
record.setdefault('voice_hotkeys_by_provider', {})['wetype'] = {'hold': voice_hotkey, 'source': 'manual'}
config.update(audio_ducking_enabled=False, disable_audio_sending=False, app_log_enabled=True)
actions = {
    'up': ('arrow_up', []), 'down': ('arrow_down', []),
    'left': ('arrow_left', []), 'right': ('arrow_right', []),
    'ok': ('return', []), 'back': ('escape', []),
    'home': ('app_switcher', []),
    'youtube': ('key_combo', ['tab']),
    'netflix': ('key_combo', ['shift', 'tab']),
    'input_source': ('key_combo', ['ctrl', 'shift', 'p']),
    'mic': ('voice_hold', []), 'power': ('disabled', []),
    'volume_up': ('system_volume_up', []),
    'volume_down': ('system_volume_down', []),
}
bindings = keys.setdefault('remote_settings', {}).setdefault('records', {}).setdefault(active, {}).setdefault('bindings', {})
for button, (kind, tokens) in actions.items():
    bindings[button] = {'kind': kind, 'keys': tokens}
for path, data in ((config_path, config), (keys_path, keys)):
    path.write_text(json.dumps(data, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
print('Configured selected remote; backup:', backup)
```

## 7. 必须做的现场验收

请 Agent 先启动监听，**真正 READY 后**才让机主按键，给出足够操作时间，不在探针退出后要求用户补按。

1. 在独立记事本或测试文本框逐键测试：方向、OK、返回、主页、YouTube、Netflix、输入源、侧面音量。推荐动作分别为方向、Enter、Esc、窗口切换器、Tab、Shift+Tab、Ctrl+Shift+P、系统音量。电源默认留空。
2. 按住语音键，说一句有辨识度的中文，例如“今天用遥控器开始写代码”，松开。Agent 必须实际读到文本框里的识别结果或由机主确认，不能人工把目标句打进去作为验收。
3. 从声音链路检查：音频通知/PCM → CABLE 播放 → 微信麦克风实际打开 → 中文上屏。按键验收应有 `received/delivered > 0`，不是只看安装组件正常。
4. 用之前正常的视频或音乐播放器播放一段声音。先不按语音键，再按住说话并松开，确认声音能保持/恢复。**仅系统测试音能响，不等于视频声音正常。**
5. 正常完全退出并用自己的启动入口重开，再测一次。电脑重启和长时间休眠要单独验收，没测不能写成完成。

## 8. 卡住时怎样分支

| 证据 | 下一步 |
|---|---|
| Windows 已连接，但电池/HID/ATVV 的实时 GATT 请求不可达 | 先排除其他桥接程序与旧主机占用；机主同意后仅删除并重配这只遥控器，取电池 10 秒，再 Back+Home 配对。本次旧绑定下失败，重配后才恢复 |
| HID 特征查询 AccessDenied | 可能已由 Windows HID 驱动持有；这不是“没有按键”的证明，继续查看程序设备专属接收 |
| Raw Input 为零 | 不能单独判定设备不发数据；检查监听是否真就绪、设备名编码和程序 HID 接收。若写探针，GetRawInputDeviceInfoW 必须配 Unicode 解码 |
| 报告全部 length_rejected | 先看真实长度；同 VID/PID 有 1/2/8 字节变体，本文包含 1 字节兼容，但现场实际是 8 字节，不要先入为主 |
| 订阅成功但音频/控制一直为零 | 确认补丁已应用、使用 ATVV 直订和真实能力响应，而不是只依赖 ETW |
| 有音频但没有转写 | 核对活动设备记录、WASAPI CABLE Input、微信 CABLE Output、快捷键、关闭音频发送是否误开 |
| 视频没声音 | 查实际默认物理输出及每个播放器的路由/静音。测试音和视频分别验证。本次电脑真实扬声器能响，而默认输出在电视；恢复 Realtek 播放后视频恢复，同时关闭了自动压音 |
| 某一机器驱动布局/PDB 不支持 | 保存精确阶段、系统/蓝牙版本和脱敏日志。不能猜偏移、取消设备过滤、波及普通键鼠，不能保证换适配器必解决 |

上游 [ATVVoice](https://github.com/b0o/ATVVoice) 提供 ATVV 研究；[同型号变体修复 PR](https://github.com/BenjmSek/windows-remote-mic-app/pull/1) 是参考。本指南的补丁没有引入“伪造 AUDIO_START”等绕过真实语音会话的改动。
